<Info>
  Automations require the **Trader** plan or above. See [plans](/reference/plan-comparison).
</Info>

We'll build a real one end to end: *notify me on Discord when NVDA is oversold on above-average volume.* Ten minutes, and the pattern generalises to anything else you want to watch.

Every automation is a left-to-right flow on the canvas. Only the ends are compulsory:

```
Asset  →  Signal(s)  →  [Logic]  →  [Agent]  →  Action
```

What each node does is set out in [the six node types](/automations/overview).

## 1. Start a new one

Open **Automations** in the sidebar and click **Create Automation**. You get two options: **Start from scratch**, or **Choose a Template**. Pick *start from scratch*. There are 45 templates worth browsing later, but building one yourself is how the pieces make sense.

Either way you land on the same canvas, with two nodes already placed and wired together: **Asset** on the left, **Action** on the right. A small toolbar floats at the top left holding the only three things you can add, **Signal**, **Schedule**, and **+ Agent**. Click any node and its settings open in a drawer on the right, which is where every field below lives.

## 2. Name it, then set the asset

Click the **Asset** node. The drawer opens with a name box at the top, placeholder *Automation name...*. Fill it in: Tradion refuses to save an unnamed automation.

Underneath, search `NVDA` in the symbol field. The live price appears as you type, so you can confirm you have the right instrument.

<Tip>
  Asset type decides which signals you can use next. Earnings and Options Flow are stocks-only; [signal types](/automations/signal-types) has the grid.
</Tip>

## 3. Add the first signal: RSI

Click **Signal** in the toolbar. A condition node drops onto the canvas between the asset and the action. Click it and configure:

<CodeGroup>
```yaml Signal 1
type: Technical indicator
indicator: RSI
period: 14
timeframe: 1 day
operator: Crosses Below (one-shot)
value: 30
```
</CodeGroup>

**RSI** is the Relative Strength Index, a 0 to 100 score measuring how hard a stock has been pushed in one direction recently. Below 30 is conventionally called **oversold**, meaning sold down far enough that some traders expect a bounce. That convention breaks down in a strong downtrend.

The dropdown offers *Crosses Below (one-shot)* and *Goes Below (continuous)*. Pick the crossing one: it fires on the single check where RSI passed through 30, while the continuous one stays true for as long as RSI sits under 30, which is eighty alerts about the same afternoon. Full explanation: [operators](/automations/operators).

## 4. Add the second signal: volume

Click **Signal** in the toolbar a second time. A **Logic** node appears on its own between the two signals; you never draw it, and it disappears again if you delete one of them. The toolbar stops you at ten signals.

<CodeGroup>
```yaml Signal 2
type: Volume
value: 2        # twice the symbol's normal volume
```
</CodeGroup>

The number you type is a **multiple of normal**, not a share count. `2` means twice the average, `1.5` means half again as busy as usual. "Normal" is the 20 bars before the current one, so today's own trading is never counted into the average it is measured against.

<Note>
  Volume has no operator dropdown. The check is always *above*. You're asking "is it busier than `N` times normal right now?"
</Note>

### Picking the number

Start at `2` and adjust. Below about `1.5` you'll catch ordinary busy mornings; above `3` you'll only see genuine events, and on a quiet symbol you may see nothing for months. A ticker with fewer than 11 bars of history has no usable average and reports *no average volume available* instead, covered on [signal types](/automations/signal-types).

Set the Logic node to **AND**, since you want both true at once, not either. It is the one node with no drawer: click the node itself on the canvas and it flips between **AND** (all match) and **OR** (any match).

## 5. Choose where the alert goes

Click the action node and turn on a channel. For this one, pick **Discord**: paste a webhook URL from your server (**Server Settings → Integrations → Webhooks**). Email, Telegram, in-app, and your own webhook endpoint all work too, and you can turn on several at once. Setup for each is in [the Action node](/automations/notifications).

Each channel gets a **Personal Insights** switch, controlling whether your own trading history can appear in the message. It is off by default for Discord, Telegram, and webhook. Leave it off anywhere other people can read.

<Warning>
  Telegram has a hidden step: there is no Telegram panel in Settings, so you message the bot first and paste a numeric chat ID in here. [The Action node](/automations/notifications) has it.
</Warning>

Then write the message. Template variables use **single** braces:

```
{symbol} oversold at {price}, {signal}
```

A name that isn't a real variable is printed literally rather than replaced, so check your spelling against the list on [the Action node](/automations/notifications).

## 6. Sanity-check the threshold

Do this before you click Create, because Create starts it running. Tradion has no frequency estimator, so ask [AI Quant Research](/research/quant-research) how many times in the past year NVDA's daily RSI crossed below 30, then decide whether that many messages is something you would still read in month three.

<Check>
  A handful of alerts a month gets acted on. Forty a day gets muted, and a muted alert is worth nothing.
</Check>

Too frequent? Tighten the threshold or lengthen the timeframe.

## 7. Create it

Click **Create** at the top of the canvas. If a required field is empty the canvas refuses and shows why; otherwise it saves and returns you to the list.

<Warning>
  **A new automation is created switched on.** There is no separate activate step: Tradion picks it up within 60 seconds and re-checks it every 60 seconds after that. The **Active** toggle on its card in the list is how you stop it again.
</Warning>

Were every signal a price or volume check on a US stock, Tradion would also watch the live trade feed between 9:30 AM and 4:00 PM ET and react within about a second. Ours has an RSI signal on it, so it runs on the 60-second cycle instead. The cycle does not stop at the closing bell; [automations overview](/automations/overview) covers what gets checked overnight.

### In plain English

You have not scheduled anything. You have written down a question, and Tradion now asks it once a minute until you pause the automation or delete it: *are both of these true right now?* Nobody is watching the gaps between checks, so a condition that flickers true for ten seconds can pass unseen. Levels that hold for minutes work here; ones that hold for seconds do not.

## Adding an AI agent (optional)

Open **+ Agent** in the toolbar and pick a type from the list. The node lands ahead of the action, and the message then arrives as a short research brief (news, filings, insider activity) instead of a bare price alert. Agent nodes spend from a monthly allowance, 50 runs on Trader and 500 on Quant, so keep them off high-frequency triggers. Details: [the AI Agent node](/automations/ai-agent-node).

## The two mistakes people make here

Fires constantly? You picked a *Goes* operator where you wanted the *Crosses* version. Fix that before adding a cooldown, see [operators](/automations/operators). Never fires? Usually the volume number is too high, or RSI never reached 30, and [runs and history](/automations/runs-and-history) shows you what was checked rather than leaving you to guess.
