Every automation ends at an Action node. It decides where the alert goes, how much of your trading history goes into it, how it reads, and how often it repeats. New automations start with **In-App** on and nothing else.

## The five channels

Turn on as many as you like. Each is delivered on its own, so one failing does not hold up the others, and all render the same template.

<Tabs>
  <Tab title="In-app">
    A live pop-up inside Tradion plus a permanent entry in your notification list. Nothing to configure and nothing to break. Keep it on while testing a new automation.
  </Tab>
  <Tab title="Discord">
    Alerts arrive as embedded cards. You need a **webhook URL**, a private address Discord gives you that lets an outside service post into one channel. Anyone holding it can post there, so treat it like a password.

    In Discord: **Server Settings → Integrations → Webhooks** (you need Manage Webhooks), **New Webhook**, pick the channel, **Copy Webhook URL**, paste it into the Action node. Tradion accepts HTTPS on Discord's domains only. A long brief splits across up to three messages.
  </Tab>
  <Tab title="Email">
    Leave the address blank to use your account email, or type another. Best for anything firing daily or slower, since an inbox is a poor place for an alert you must act on within the hour.
  </Tab>
  <Tab title="Telegram">
    Alerts come from `@TradionBot`, and there is no Telegram panel in Settings, so you do two things yourself.

    Open Telegram, search `@TradionBot`, press **Start**. Telegram blocks bots from messaging anyone who has not spoken first, so skipping this means no alert ever arrives. Then message `@userinfobot` for your numeric chat ID (a number, not your `@username`) and paste it into **Telegram Chat ID**. Digits and a leading minus only.

    For a group, open [web.telegram.org](https://web.telegram.org), click the group, and read the number after `#` in the address bar. A group ID starts with a minus and that sign is part of it. A wrong ID fails quietly.
  </Tab>
  <Tab title="Webhook">
    An HTTPS POST of the alert as JSON to an endpoint you control. It carries an **HMAC** signature, a fingerprint of the body computed with a shared secret, so your server can confirm the request came from Tradion unaltered, plus a key for discarding duplicates.

    Shape, header, and verification code: [webhook payloads](/reference/webhook-payloads). Non-HTTPS addresses and anything on a private network are refused.
  </Tab>
</Tabs>

## Personal Insights

Once a channel is on, it gets its own **Personal Insights** switch. Defaults: **on** for in-app and email, **off** for Discord, Telegram, and webhook.

It decides whether your own trading history can appear in that channel's message. On, the analysis an Agent node produces may carry lines drawn from your Trade Autopsy record and portfolio: positions held, documented mistake patterns, entry, exit and risk-management scores, saved playbook rules, win rates by symbol. Off, Tradion filters those lines out of the agent's summary, sections, key findings, risks, and action items before sending.

<Warning>
  The filter matches a fixed list of personal phrasings line by line. It is not a rewrite, so a sentence describing your habits in wording the list does not cover can still get through. Before pointing an automation with agents at a public Discord, fire it once to in-app and read what it produced.
</Warning>

### In plain English

The analysis is written once, with your history available to it. Each channel gets a copy, and the switch decides whether the private lines are stripped from that copy. Off suits anywhere other people can read; on suits your own inbox. With no Agent node there is no analysis to filter, so the switch changes nothing.

Two things sit above it: turning off AI Memory personalisation in Settings keeps your history out of every agent everywhere, and in automations the model is separately told never to print your autopsy scores.

## Writing the message

A **preset** button above the box fills in a template matching what is on the canvas, one at a time: **Signal** with no agents, **Signal + Agent** with one, **Signal + Each Agent** with several, **Report** once a Report Writer is present. Adding or removing an agent rewrites the template only if you had not edited it yourself.

Three variables always work. Click a chip to insert one at the cursor.

| Variable | Resolves to |
| --- | --- |
| `{symbol}` | The ticker being watched |
| `{price}` | The price when the automation fired |
| `{signal}` | A readable description of what became true |

With Agent nodes on the canvas an **Agent vars** row appears: `{research_agent}`, `{fundamental_agent}`, `{sentiment_agent}`, `{chart_agent}`, `{market_brief_agent}`, `{report_agent}`. Each is filled by the agent of that name, `{report_agent}` by the Report Writer's memo. Braces are single, never double.

```
{symbol}: {signal}
Price: {price}

{report_agent}
```

Type an agent variable whose agent is not on the canvas and a yellow note names it. Leave it and **the whole line containing it is deleted** rather than left as a gap, so keep agent variables on their own lines. Same if an agent returns nothing. A name that is not a variable, `{ticker}` say, prints as typed.

The **Example Preview** underneath fills every variable with sample values so you can see the shape. It is a mock-up, not your data.

## Footer and cooldown

The **Footer** is one line at the bottom of Discord and email alerts. Leave it blank to hide it. Useful for naming the automation when several post into one Discord channel.

A **cooldown** is a minimum quiet period: once an automation fires it will not fire again until the cooldown elapses, however long the condition stays true. Five presets, 5m, 15m, 1h (the default), 4h and 1d. Templates arrive carrying other values, and anything from 1 minute to 31 days is accepted.

With agents on the canvas the node header prints their combined run time as **Est. ~15 min · 6 agents, sequential**. Set the cooldown longer than that.

<Tip>
  A cooldown mutes repeats; it does not fix a badly written condition. If an alert repeats because you chose *Goes Above (continuous)* over *Crosses Above (one-shot)*, change the [operator](/automations/operators) first.
</Tip>

## Delivery, retries, and failure

Sending is queued, which is what makes retries possible. A timeout or dropped connection is retried three times with a growing gap of roughly two seconds, then four, then eight. Configuration errors, such as a revoked Discord webhook, are not retried because retrying changes nothing. After about fifteen seconds Tradion gives up and records why.

<Warning>
  A failing channel does not pause the automation. A revoked webhook or a bouncing address goes on failing quietly while the automation goes on firing. **Automations → Runs** is the only place this shows.
</Warning>

<AccordionGroup>
  <Accordion title="Discord alerts stopped">
    Webhook URLs are revoked when the channel is deleted, when someone resets the server's integrations, or when the webhook is deleted. Create a new one and paste the new URL.
  </Accordion>
  <Accordion title="Telegram alerts never started">
    You have not pressed Start on `@TradionBot`, or the chat ID is wrong. A group ID missing its leading minus is the usual version.
  </Accordion>
  <Accordion title="Email is missing">
    Check spam, then the address on the Action node: one typed there overrides your account email.
  </Accordion>
  <Accordion title="Webhook returns an error">
    Your endpoint must be HTTPS and reachable from the public internet. Private and local addresses are rejected before the request is made.
  </Accordion>
</AccordionGroup>
