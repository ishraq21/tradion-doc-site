### On visuals

Pages use **diagrams, not screenshots.** Twenty-five annotated SVGs, generated by `scripts/build-illustrations.mjs` in the Tradion palette, containing only placeholder data — no balances, no P&L, no names. Mermaid handles flows inline.

That was a deliberate call for three reasons. Screenshots of a trading app show somebody's money. There is no seeded demo account yet. And a diagram that labels *what a panel is for* stays true through a redesign, while a screenshot does not.

The Playwright pipeline is still here and still worth running once a demo account exists — real screenshots are better for "where do I click" pages like the tour and the brokerage connection. Diagrams are better for "what does this mean" pages, which is most of the site. Treat them as complementary rather than a migration.

## Why these choices

**Mintlify.** You are one person shipping fast; you should be writing docs, not maintaining a docs framework. Mintlify gives you search, dark mode, image lightbox, `llms.txt` for AI agents, and a "Copy for ChatGPT/Claude" button on every page — all configured. The `docs.json` here already matches your brand tokens (`#459e6b` emerald, Space Grotesk headings, Inter body, dark default).

**New-user-first IA.** The nav is organised by the loop stations from your README, not by your codebase. A user who has just signed up reads top to bottom and never has to know that Profile used to be two screens or that Pulse got merged into it.

**Automated screenshots.** You have 12 live views and dozens of sub-components. Manual capture decays within two sprints. The script navigates by seeding `tradion_active_view` in localStorage (you have no React Router, so URL navigation isn't available), authenticates by minting the same HS256 JWT your server issues, and freezes `Date` and all animation so runs are diffable.

## Phases

### Phase 1 — Make the app screenshottable (~1 day, engineering) — optional now

This is the only work that touches the main app, and it unblocks everything else.

1. **Add `data-doc` attributes** to the ~45 components that cropped screenshots target. Grep `scripts/shots.ts` for `data-doc=` to get the list. One-line change per component; they're inert in production.
2. **Write `scripts/seed-docs-demo.js`** — a seeder producing the demo account described in `scripts/README.md` (40 trades, 5 autopsies, 4 automations, a 14-position portfolio, 90 days of snapshots). Reuse the patterns in your existing `scripts/` seeders.
3. **Stand up a staging deploy** the capture script can hit, or just run it against localhost with a local seeded DB.
4. **Tag anything live-updating** with `data-doc-freeze` — the ticker tape, market clock, and any "N seconds ago" label.

### Phase 2 — Capture and triage (~half a day)

```bash
cd docs-site && npm install && npx playwright install chromium
DOCS_BASE_URL=http://localhost:3000 JWT_SECRET=… DOCS_DEMO_USER_ID=… npm run shots
```

Expect a handful of failures on the first run — missing hooks, panels that need longer settle times. Fix, re-run, review the images as a set. This first review is worth doing carefully: it's the first time you'll see every screen of your product side by side, and it tends to surface UI inconsistencies nobody had noticed.

### Phase 3 — Writing — done

All 46 pages are written, ~45,000 words, verified against the code rather than the README. What remains is editing rather than drafting: read them as a reader would, and cut.

### Phase 4 — Ship (~2 hours)

2. Add the custom domain `docs.tradionlabs.com` and the `CNAME` record Mintlify gives you.

- Watch Mintlify's search analytics — queries returning nothing are a direct list of pages you haven't written.

## Deliberately out of scope

**A public API reference.** Tradion has no public API — CORS is locked to first-party origins, there's no API key system, and auth is an httpOnly cookie or a first-party extension bearer token. Documenting one would invite support questions you can't answer. The one genuinely external surface is the outbound automation webhook, which is covered at `reference/webhook-payloads`.

**Anything about dead code.** `ViewState.WATCHLIST` and `ViewState.TRADE_GPT` are declared but unreachable; `Dashboard.tsx`, `AIMemory.tsx`, `Briefing.tsx`, `Pricing.tsx`, and `Terminal/ChatInterface.tsx` are orphaned. None appear in the docs. Worth deleting from the app while you're at it.

**The Chrome extension.** It lives in a different repo. When you're ready, it slots in as a group under Research & Analysis next to Lens.
